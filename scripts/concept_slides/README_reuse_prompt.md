# Reusing the illustrated-deck workflow in another project

The prompt below is meant to be pasted into a Claude Code session in a
different project. It describes the whole workflow this repo arrived at on
16-17 September 2026 (docs/slides/MN-proxy-full-talk-2026-09.qmd and its
concept YAML), names the files to copy, and lists the traps that cost time.
Copy the four files it names into the new project before pasting the prompt.

---

## Prompt

I want a slide deck built the way the `mn-prediction` project builds its talks. The deliverable is a `.pptx` on our own template, fully regenerated by one command, with every number read from the project's result tables, and with the "illustrated concept slide" style (icon + heading + caption rows, cards, pipelines, checklists) for the conceptual slides while figure slides stay knitted. Work in this repo; before writing anything, read the four reusable files I copied in from that project:

- `scripts/concept_slides/build_concept_slides.py` — python-pptx builder. Two modes: standalone (`spec.yaml` → its own pptx + PNG previews + placement table) and **in-place** (`--into deck.pptx`: finds each concept slide in the pandoc-rendered deck by its title, removes the empty body placeholder, draws the layout). Layouts: `icon_rows` (optional right-hand image, `heading_size`/`text_size`), `cards` (`lines` with bold "Label:" leads), `pipeline` (stacked cards when 4+), `checklist` (yes/partly/no tiles), `two_panel` (icons optional), `grid` (groups with `count_of` sums and an optional `footnote`), `title` (logos + acknowledgement, auto-shrinks a long title). Text uses `{name}` placeholders with `:.2f`, `:.0f`, `:pc`, `:sgn` formats, filled from a quantities JSON.
- `scripts/concept_slides/build_quantities.R` — evaluates the qmd's `setup` chunk as the deck would (working dir = the qmd's folder, `root` = project root), writes `<deck>.quantities.json` from the chunk's `Q` list, and renders every Font Awesome icon the YAML names as PNG (`fontawesome::fa_png`, blue by default, `name@colour` variants, status icons for checklists) into `docs/slides/img/icons/`, skipping ones that exist.
- `scripts/render_deck.sh` — `quarto render --to pptx`, then `fix_pptx_dangling_rels.py` (pandoc + a reference doc leaves a file PowerPoint refuses to open), optional `--text BODY,TABLE` (`pptx_set_text_size.py`: pandoc leaves run sizes unset so bullets inherit the master's 28 pt), optional `--forum`-style post-process for a conference template, then `--concept spec.yaml` which runs the two scripts above **last** (the text-size step would restamp the concept slides' fonts).
- `scripts/concept_slides/README_reuse_prompt.md` (this file).

Set the project up the same way:

1. **One Quarto source** `docs/slides/<deck>.qmd`, `format: pptx` with `reference-doc:` pointing at our template and `slide-level: 2`. Its `setup` chunk reads every result table once and builds a single list `Q` of every quantity the deck mentions. All prose numbers are inline `` `r f2(Q$x)` `` expressions (define `f2`, `pc`, `sgn`, `get1` helpers; make `get1` `unname()` its value, otherwise a `quantile()` name turns the JSON value into an object and the builder crashes). Figures are R chunks drawn from the tables at render time. Because pandoc's PowerPoint writer puts a figure and a following paragraph on **separate** slides, figure slides use a two-column layout: statement of what the figure shows in a 34% column, the figure in a 66% column; or a lone figure that the post-process enlarges to the content area.
2. **Concept slides** are, in the qmd, just `## Title` plus a `::: {.notes}` block. Their content lives in `docs/slides/<deck>.concept.yaml` (`deck:` names the qmd; one entry per slide with `title`, `layout`, items). The builder matches by rendered title, so a title with an inline number must be written identically in both places (`` `r f2(Q$x)` `` in the qmd, `{x:.2f}` in the YAML). Section headers are skipped when matching, so a concept slide must not share a title with a section.
3. **Icons**: Font Awesome 6 free names only (check `fontawesome::fa_metadata()`), rendered once and committed; never emoji (they do not survive PDF export and look inconsistent).
4. **Speaker notes** on every main-body slide in two parts: `SAY:` (what to say, two to four sentences) then `DETAIL:` (what the slide shows, sources, likely questions). Appendix slides need only DETAIL.
5. **House style** for a policy audience, learned from the WFP/MIMI deck and IHME's maps: titles are the question the slide answers or the claim it makes, with the live number in the title where there is one; one example country carried through the data slides, each with a small map of one real variable; a before → after opener (what a country has today → what the model adds); evaluation framed as questions with country silhouettes showing what is held out; one evaluation-summary slide with a small table and two plain-language readings; a warm palette for the one headline map and viridis for diagnostics; every model map carries an uncertainty panel and every survey map carries a reliability grade (hatching for single-cluster units, grey for none); an "accuracy translated" slide (pairwise concordance counted exactly, not inferred from a correlation; hit rate of the flagged group; ceiling); American spelling; "outcome-country combinations", never "cells", in prose.
6. **Honesty rules** that shaped the content: compare every model number with the cheapest alternative (a national number, the survey's own regional average); show per-combination results, not only averages, and say where it fails and why; label anything selected on the test data as post hoc; if you show intervals, test their coverage on held-out units and say what they measure (stability under resampling is not distance from the truth); put per-district uncertainty on the maps and a calibration check in the deck.
7. **Reproducibility**: heavy computations (bootstrap refits, held-out predictions, coverage checks) go in a script under `scripts/` that writes small CSVs under `results/tables/.../viz/`; the qmd only reads them. One command regenerates everything: `bash scripts/render_deck.sh docs/slides/<deck>.qmd --text 18,10 --concept docs/slides/<deck>.concept.yaml`. Commit the qmd, the YAML, the icons, the viz tables and the rendered pptx.

Traps I already hit, so you do not: never edit a script while `Rscript` is running it (it reads the file incrementally) — run a frozen copy; R's `sample(i, ...)` on a length-one vector samples from `1:i`, use `i[sample.int(length(i), ...)]`; python-pptx returns a new proxy object on every `slide.shapes.title` access, so test placeholders by `placeholder_format.type`, not `is`; a discrete ggplot y-axis with an explicit `limits` vector is the only reliable way to control row order under facets; long axis titles get clipped at pandoc's figure size, keep them short; LibreOffice headless is the way to preview a pptx as PNGs (`soffice --headless --convert-to pdf`, then PyMuPDF), but it can hang on some templates — convert a copy in a fresh directory with a timeout; heredocs in the shell mangle backslashes, so write patch scripts to files and run them.

Start by proposing the slide outline (sections, one line per slide, which are figures and which are concept slides, which numbers each needs from `Q`), then build the setup chunk and the first three concept slides as a sample for me to look at before doing the rest.
